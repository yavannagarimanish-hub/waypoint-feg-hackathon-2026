# Waypoint Contextual In-App Notifications

## 1. Architecture Overview

Waypoint Contextual Notifications provide an in-app intelligence layer designed to deliver timely, non-intrusive, and protective notifications to users based on their active interest signals and current journey context.

```
USER INTEREST + JOURNEY CONTEXT
              ↓
    NOTIFICATION DECISION
              ↓
RESPONSIBLE INTELLIGENCE SAFETY GATE
              ↓
      IN-APP NOTIFICATION
```

### Key Architectural Invariants
- **Local-Only In-App Notifications**: Managed via localStorage under `waypoint_notifications`, capped at 10 items.
- **No External Messaging**: No web push, SMS, email, background worker, or Firebase services.
- **User / Admin Isolation**: Notification Center bell and panel exist exclusively in the User Portal (`/`, `/user`). The Admin Portal does not display user notifications, though canonical telemetry events (`NOTIFICATION_GENERATED`, `NOTIFICATION_SHOWN`, `NOTIFICATION_OPENED`, `NOTIFICATION_DISMISSED`) flow through the standard Waypoint event stream.
- **Protection Over Persuasion**: The notification engine prioritizes user safety, session continuity, and informational updates over conversion, urgency, or staking encouragement.

---

## 2. Interest Signals Used

The notification decision engine leverages real-time interest signals derived from authoritative session state and user interaction:
- **Sports & Fixtures Explored**: Viewed events and markets in the active session and across recent navigation.
- **Tournaments Explored**: Competitions and leagues user has demonstrated genuine navigation interest in (e.g., Premier League, Wimbledon).
- **Live Rooms Joined**: Active or recently visited custom match rooms.
- **Recently Viewed Content**: Fixtures stored in `waypoint_recently_viewed` from the Customer Context Layer.
- **Betslip & Session DNA**: Active slip selections and historical play style (e.g., high activity vs. methodical analysis).

### Explicit Non-Profiling Guarantee
The system **never** infers or processes:
- Gambling vulnerability
- Emotional distress or frustration
- Financial capacity or wealth indicators
- Addiction patterns
- Protected characteristics or sensitive personal attributes

---

## 3. Journey Signals Used

Notifications are strictly mapped to the user's current Journey Stage:
1. **DISCOVERY**: General exploration, newly trending live fixtures, match status changes (e.g., fixture going live).
2. **EXPLORATION**: Context continuity on fixtures recently viewed or markets under review.
3. **DECISION**: Re-engagement reminders if a slip was abandoned, or notification of odds movements without pressure.
4. **ACTION**: In-flight wager status, settlement alerts, or network recovery assistance.
5. **COMPLETION**: Post-settlement summary, room updates, or social interaction notices.

---

## 4. Responsible Intelligence Safety Gate

Before any notification is rendered or saved, it must pass the **Responsible Intelligence Safety Gate** (`evaluateNotificationSafety`). If any safety rule fails, the notification is rejected and discarded.

### Prohibited Patterns (Hard-Blocked)
- **Urgency Pressure**:
  - Prohibited words/phrases: `act fast`, `hurry`, `limited time`, `before it expires`, `urgent`, `last chance`, `clock is ticking`.
- **Betting Frequency Cues**:
  - Prohibited words/phrases: `bet now`, `bet again`, `haven't bet today`, `keep betting`, `place another bet`, `don't miss out`.
- **Loss-Chasing & Financial Encouragement**:
  - Prohibited words/phrases: `recover losses`, `increase stake`, `win back`, `make up for`, `double down`, `risk more`.
- **Emotional Manipulation & High-Risk Friction**:
  - If the user session is under high financial velocity or elevated friction risk, promotional or decision-stage notifications are automatically suppressed.

---

## 5. Allowed Notification Examples

All generated notifications must be informative, factual, and service-oriented:
- *"England vs Croatia is now live."*
- *"You were viewing England vs Croatia. Continue where you left off."*
- *"Manchester City vs Arsenal has started."*
- *"Your Live Room 'Champions Watch' has active discussion."*
- *"Network restored. You can safely review your betslip."*

---

## 6. Telemetry & Canonical Event Layer

Notifications emit canonical events only upon explicit user or engine state actions (no passive emission leaks):
- `NOTIFICATION_GENERATED`: Generated by the engine and accepted by the Safety Gate.
- `NOTIFICATION_SHOWN`: Emitted when the user opens the notification drawer/center.
- `NOTIFICATION_OPENED`: Emitted when the user taps on a specific notification to navigate.
- `NOTIFICATION_DISMISSED`: Emitted when the user explicitly dismisses a notification.

---

## 7. Prototype Limitations

- **Browser-Session Scoped**: Operates on client-side state in `localStorage` (`waypoint_notifications`).
- **No Background Polling**: Triggers evaluate on active journey stage transitions, fixture view events, and custom room entries.
- **Cap**: Maximum 10 notifications retained, sorted latest first.
- **Reset Demo**: Fully wiped when the user clicks "Reset Demo" alongside session memory, recently viewed, and live rooms.
